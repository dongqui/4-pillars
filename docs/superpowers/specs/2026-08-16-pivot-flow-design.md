# 랜딩 → 홈 흐름 설계 (2026-08-16)

피벗 이후의 첫 동선을 붙인 기록. 대상 이슈는 [B24 #51] 카드 컴포넌트 · [B26 #53] 랜딩 교체 ·
[B10 #35] 리빌 · [B25 #52] 홈 교체. [B08b #33] 라이트 퍼널은 폐기했다(아래 결정 1).

시안은 claude.ai/design 프로젝트 `42e876d6-1a2a-488e-93aa-825a838687ce` 의
`Character Card` · `Saju Pivot Flow` · `Saju Character Reveal` · `Saju Home`.
로컬에 없으면 DesignSync MCP 의 `get_file` 로 받는다 (`design/pivot/README.md` 참고).

## 흐름

```
/ (랜딩) → /funnel (5스텝) → /reveal (리빌) → /home (탐색 허브)
                                                 ├ 리포트  → /report?profile=…  (저장 전이면 /login)
                                                 ├ 관계 지도 → /map
                                                 └ 궁합    → 자리만
```

입구는 하나다. 시각·출생지·성별까지 처음에 다 받고, 리포트로 넘어갈 때 추가 입력이 없다.

## 결정

### 1. 입력은 한 번만 받는다 — 기존 퍼널 그대로

한때 캐릭터용 라이트 퍼널(생년월일 1스텝)을 따로 두고 리포트에서 나머지를 받는 투 트랙을
만들었다(시안·B08b가 그 모양이다). **폐기했다.** 입력을 두 번 받는 구조는 무료 → 유료 전환
경로 한복판에 재입력을 놓는다. 이제 랜딩 CTA 는 기존 다섯 스텝 퍼널로 곧장 간다.

그래서 익명 캐릭터 전용 저장소도 필요 없다. 퍼널이 이름·성별까지 받으므로 입력이
`createProfileSchema` 를 그대로 만족하고, **기존 드래프트 시스템**(`src/lib/drafts/`,
Redis + 토큰 쿠키, 로그인 시 프로필 승격)이 원래 자리를 지킨다 — B08b 의 "신규 설계 금지"가
가리키던 것이 이것이다.

리빌과 홈은 방금 저장된 것을 서버에서 다시 읽는다: 로그인이면 프로필(`/reveal?profile=`),
비로그인이면 드래프트. 생년월일을 URL 로 나르지 않으려는 것이다(리퍼러·기록·로그에 남는다).
저장이 아예 실패하면 보여줄 캐릭터가 없으므로 홈으로 보내고 홈이 빈 상태를 안내한다.

### 1-1. 무료 리포트는 로그인 전에 보여준다

`/report` 는 프로필 파라미터가 없으면 픽스처 데모를 보여줬다("익명 실데이터는 이번 범위 밖"이라는
주석과 함께). 이제 드래프트가 있으면 **그 사람의 실데이터로 무료 섹션을 렌더한다.**

전환은 리포트 안에서 일어난다:

```
/report (무료 4섹션, 실데이터)
  → 잠긴 섹션 CTA "로그인하고 전체 결과 보기"
  → /login → OAuth 콜백이 드래프트를 프로필로 승격
  → /report?profile=<새 id>
  → CTA 가 "전체 결과 보기" → /checkout?profile=<id>
```

승격과 결제 배선은 이미 있던 것이다(`promoteDraft`, `LockedSections`). 비어 있던 칸은 "비로그인이
자기 무료 리포트를 본다" 하나였다. 프로필 행과 드래프트가 `ReportSubject` 라는 같은 모양을 쓰게
해서 채웠다 — id 와 결제 여부는 "무엇을 보여줄지"가 아니라 "어디로 보낼지"의 문제라 페이지가 따로 든다.

### 2. 홈은 로그인을 요구하지 않는다

기존 `/home` 은 세션이 없으면 `/login` 으로 보냈다. 무료 캐릭터로 사람을 모으는 흐름이 로그인
벽에서 끊기면 피벗이 성립하지 않으므로 이 가드를 걷었다.

- 로그인 + 프로필 있음 → 프로필들이 셀렉터에 선다
- 그 밖 + 드래프트 있음 → 아직 저장되지 않은 한 장
- 둘 다 없음 → 빈 상태(시안에 없는 화면) + 퍼널 CTA

프로필이 하나라도 있으면 드래프트는 보여주지 않는다. 이미 승격됐거나 곧 사라질 값이고,
저장된 것과 저장되지 않은 것이 한 목록에 섞이면 무엇이 남는지 알 수 없다.

### 3. `buildPillars` 를 갈라낸다

`BirthInput.gender` 는 대운 방향에만 쓰이는데 타입상 필수라, 성별을 묻지 않는 입구는 가짜 값을
넣어야 했다(다른 브랜치의 `dayPillarOf` 가 `gender: "male"` 을 주석과 함께 넣고 있다).
간지는 성별과 무관하므로 `buildChart` 에서 성별 없는 `buildPillars` 를 떼어냈다.
`characterFromBirth(생년월일)` 가 그 위에 선다. 두 브랜치가 합쳐질 때 `dayPillarOf` 의
`gender: "male"` 은 지울 수 있다.

### 4. 퍼널의 계산 화면과 리빌은 한 장면이다

퍼널 마지막(저장 요청 대기)과 리빌 첫 페이즈가 라우트는 다르지만 사용자에게는 이어지는 한
화면이라, 같은 컴포넌트(`CharacterLoading`)를 쓰고 1.1초씩 나눠 가진다. 합쳐서 시안의 2.2초다.
기존 `AnalyzingScreen`(밝은 배경 + 체크리스트)은 리빌과 톤이 어긋나서 걷어냈다.

### 5. 리빌 → 홈 핸드오프는 sessionStorage

`/home?from=reveal` 로 두면 새로고침·링크 공유 때마다 연출이 다시 재생된다. 한 번 쓰고 지우는
값이어야 해서 `sessionStorage`(`saju:handoff`)로 나른다. 홈은 state 가 아니라 ref 로 클래스를
붙인다 — 서버에는 스토리지가 없어 첫 렌더에 알 수 없고, state 로 두면 그 사실 하나 때문에 전체가
한 번 더 그려진다.

## 카드 컴포넌트가 크기를 다루는 방식

시안 그대로 **1080px 캔버스에 그리고 `zoom: zoomW/1080` 으로 줄인다.** 폭마다 폰트를 다시 잡으면
장면명 한 줄·칩 줄바꿈·한자 위치가 따로 논다. `zoomW` 를 `w` 보다 작게 주면 글자 크기와 높이는
그대로 두고 가로만 늘어난다(홈 데스크톱이 `w=500 / zoomW=460`).

`zoom` 은 CSS 로 계산할 수 없어 폭을 숫자로 받아야 한다. 그래서 카드를 쓰는 화면은
`useViewportWidth()` 로 실제 폭을 재는 클라이언트 컴포넌트다. 서버 렌더는 모바일 폭(390)으로
시작한다 — 데스크톱에서 한 번 커지는 쪽이 모바일에서 잘려 보이는 쪽보다 낫다.

한자 워터마크 폰트(Nanum Myeongjo)는 Google Fonts 기본 URL 로 받는다. `&text=` 서브셋 경로
(`fonts.gstatic.com/l/font`)는 CORS 헤더를 주지 않아 `@font-face` 로드가 차단된다.

## 시안과 다르게 한 것

- **랜딩 푸터** — 시안에는 로고 한 줄뿐이지만 법률 링크·사업자정보를 남겼다. 통신판매업자 표시 의무다.
- **다크 섹션의 궁합 줄** — "지금" → "준비 중". 화면이 아직 없다.
- **홈 액션 그리드의 궁합** — 링크 대신 자리만. 링크로 두면 막다른 길이 된다.
- **모바일 경계** — 시안 760px, 구현 768px(Tailwind `md:`). 8px 어긋나면 그 구간에서만 카드 폭과
  단 수가 따로 논다.
- **입력 화면** — 시안의 1스텝 라이트 퍼널을 쓰지 않고 기존 5스텝 퍼널로 대체했다(위 결정 1).
  랜딩 카피도 "30초 · 생년월일만" 에서 "1분 · 생년월일시" 로 같이 옮겼다.

## 하지 않은 것

- **공유** — B10 에서 폐기된 항목(공유 버튼·수신자 화면·미니 도감)은 만들지 않았다.
- **OG 이미지** (B11) — 별도 이슈.
- **`/map`** — `claude/wireframe-design-planning-d51640` 에 있다. 홈에서 링크만 걸어 두었고,
  그 브랜치가 합쳐지기 전에는 404 다.
- **60종 렌더 스냅샷 육안 검수** — 60종이 파라미터만으로 렌더되는 것은 테스트로 확인했지만
  대비·줄바꿈을 눈으로 본 것은 대표 몇 종뿐이다.
- **로그인 사용자의 홈** — 프로필 → 캐릭터 매핑은 단위 테스트로만 확인했다(브라우저 확인은 익명 경로).
- **익명 리포트 생성 레이트리밋** — ⚠️ 출시 전 필요. 무료 리포트가 실데이터로 열리면서
  비로그인도 LLM 생성을 유발할 수 있게 됐다. 해석 캐시는 원국 단위라 같은 사주는 한 번이지만,
  생년월일을 바꿔가며 `POST /api/profiles` → `GET /report` 를 반복하면 상한이 없다.
  [B18](https://github.com/dongqui/4-pillars/issues/45) 이 말하는 "익명 생성 레이트리밋"이 이것이고,
  `claude/wireframe-design-planning-d51640` 의 `src/lib/maps/rate-limit.ts` 가 같은 문제를 이미 푼다.
