# 법률 페이지 (이용약관·개인정보처리방침·사업자정보) 설계 문서

**날짜:** 2026-08-12
**출처:** 사업자등록증명원 (`헤일메리랩스`, 2026-08-12 발급). 사업자 값의 단일 출처.

## 1. 목표

유료 사주 리포트를 파는 전자상거래 서비스로서 법적으로 표시 의무가 있는 세 가지를 화면에 올린다.

- **사업자정보** — 상호·대표자·사업자등록번호·주소·통신판매업 신고번호·연락처 (전자상거래법 10조 표시 의무).
- **이용약관** — 서비스 정의, 유료 결제, **청약철회·환불 정책** 포함.
- **개인정보처리방침** — 수집 항목·목적·보관·위탁·권리.

지금 이 셋을 담는 페이지가 저장소에 없다 (`grep -i terms/privacy/policy/legal` → 0건). 새로 만든다.

### 비범위 (YAGNI)

- checkout·funnel·report 등 다른 화면에 링크 삽입. (요청 시 후속으로 추가 가능 — 공용 푸터가 없어 각 화면 개별 작업이라 지금 묶지 않는다.)
- 약관 **동의 체크박스**를 checkout에 배선하는 일. checkout에는 이미 동의 UI가 있고(참고: `2026-08-05-checkout-page-design.md`), 이 작업은 "읽을 수 있는 페이지"를 만드는 데 한정한다.
- 약관 버전 관리·동의 이력 저장·개정 이력 페이지.
- i18n / 일본어. 다국어 배선 없음.
- `@tailwindcss/typography` 도입. 설치돼 있지 않다 — prose 스타일은 유틸리티 클래스로 직접 준다.

## 3. 라우팅과 파일 구조

Next 16 App Router. 라우트 그룹 `(legal)`로 묶어 공용 레이아웃을 공유한다. URL에는 `(legal)`이 드러나지 않는다 → 실제 경로는 `/terms`, `/privacy`, `/business`.

```
src/app/(legal)/
  layout.tsx          # 공용 셸: 상단 뒤로가기(홈), 읽기 좋은 max-width 본문, 최종 개정일 표시
  _lib/company.ts     # 사업자정보 단일 소스 (§4)
  _components/
    LegalPage.tsx     # 제목 + 개정일 + 본문 슬롯을 감싸는 프레젠테이션 래퍼
    Section.tsx       # 조/항 제목 + 문단을 일관되게 렌더 (선택 — 반복이 많으면 도입)
  terms/page.tsx      # /terms
  privacy/page.tsx    # /privacy
  business/page.tsx   # /business
```

각 `page.tsx`는 `export const metadata`로 `title`/`description`을 준다. 색인은 허용하되(공개돼야 하는 페이지), 본문은 정적이라 추가 캐시 지시는 두지 않는다.

> **주의:** 이 저장소의 Next(16.2.10)는 학습 데이터와 다를 수 있다. 구현 단계에서 라우트 그룹·`layout.tsx`·`metadata` 규약을 `node_modules/next/dist/docs`에서 먼저 확인한 뒤 코드를 쓴다 (AGENTS.md).

## 4. 사업자정보 단일 소스 — `src/app/(legal)/_lib/company.ts`

사업자 값이 footer·사업자정보 페이지·약관 세 군데서 쓰인다. 값을 세 번 적으면 통신판매업번호가 확정될 때 한 곳을 빠뜨린다. `as const` 객체 하나로 모으고 모두 여기서만 참조한다. (타입으로 오탈자·누락을 막는 방식 — 사용자 선호 패턴.)

```ts
export const COMPANY = {
  name: "헤일메리랩스",
  ceo: "김동진",
  registrationNumber: "432-33-01882",           // 사업자등록번호
  address: "경기도 이천시 경충대로2762번길 29-107, 102-S21호 (관고동)",
  // TODO(통신판매업): 신고 완료 후 실제 신고번호로 교체. 예: "제2026-경기이천-0000호"
  mailOrderSalesNumber: "통신판매업 신고 준비중",
  contactEmail: "hailmarylabs@gmail.com",

```

## 5. 페이지 콘텐츠

법률 문안은 변호사 감수를 받은 것이 아니라 **검증된 표준 템플릿을 이 서비스에 맞게 채운 것**이다. 확정이 필요한 자리(통신판매업번호)는 화면·주석에 드러낸다. 각 페이지 상단에 "최종 개정일: 2026-08-12"를 둔다.

### 5.1 이용약관 `/terms`

- **제1조 목적·정의** — "회사"(헤일메리랩스), "서비스"(생년월일시 기반 AI 사주 리포트), "리포트", "이용자".
- **제2조 서비스 내용·성격 고지** — AI가 생성하는 해석이며 오락·자기이해 목적이고 전문 상담(의료·법률·재무)이 아님을 명시.
- **제3조 이용계약·회원** — 소셜 로그인으로 성립.
- **제4조 유료 서비스·결제** — 리포트 잠금 해제가 유료임, 결제수단은 PortOne을 통한 카드/간편결제(이니시스 등).
- **제5조 청약철회 및 환불** — 핵심:
  - 리포트가 **생성·제공(열람)되기 전**: 결제일로부터 7일 이내 청약철회 시 **전액환불**.
  - 리포트가 **생성·제공(열람)된 후**: 「전자상거래 등에서의 소비자보호에 관한 법률」 제17조 제2항 단서(복제 가능한 재화 등으로 제공이 개시된 디지털 콘텐츠)에 따라 **청약철회 제한**. 단, 회사의 귀책(오류·미제공)일 때는 환불.
  - 환불 요청·문의: `hailmarylabs@gmail.com`.
- **제6조 이용자 의무** — 타인 정보 도용 금지 등.
- **제7조 책임의 한계** — 리포트 해석의 정확성·특정 결과 보장 안 함.
- **제8조 준거법·분쟁** — 대한민국 법, 관할.
- 최종 개정일.

### 5.2 개인정보처리방침 `/privacy`

- **수집 항목** — (1) 소셜 로그인 식별자·이메일·닉네임, (2) 사주 입력값: 생년월일시·성별·(선택)출생지, (3) 결제 관련 정보(거래 식별자 등 — 카드정보는 PG가 처리, 회사 미보관).
- **수집·이용 목적** — 리포트 생성·제공, 결제·환불 처리, 문의 응대.
- **보관 기간** — 회원 탈퇴 시 파기 원칙, 전자상거래법상 거래·결제 기록은 법정 기간(예: 5년) 보관.
- **처리위탁** (표) — PortOne·KG이니시스=결제 처리, Neon=DB 저장, Upstash(Redis)=세션, 소셜 로그인 제공자=인증. (실제 의존성 `package.json` 기준.)
- **정보주체 권리** — 열람·정정·삭제·처리정지 요구, 행사 방법(이메일).
- **파기 절차·방법**, **개인정보 보호책임자**(대표자·이메일), **고지 의무**(개정 시).
- 최종 개정일.

## 6. 링크 노출 — `FooterCta.tsx`

`FooterCta`의 하단 바(현재 로고 + 태그라인 행)에 링크 3개를 추가한다.


## 7. 테스트

Vitest. 정적 콘텐츠라 스모크 수준으로 충분하다.

- 세 페이지 컴포넌트가 예외 없이 렌더된다.
- 각 페이지에 **법정 표시 항목이 실제로 존재**한다:
  - `/business`: 상호·사업자등록번호(`432-33-01882`)·문의 이메일.
  - `/terms`: "청약철회" 및 "열람 후" 환불 제한 문구, 이메일.
  - `/privacy`: 수집 항목·위탁·문의 이메일.
- `COMPANY` 상수를 import한 렌더 결과에 상호/등록번호가 나온다 (단일 소스가 실제로 화면까지 도달하는지).
- `FooterCta` 렌더 결과에 세 링크의 `href`(`/terms`, `/privacy`, `/business`)가 존재한다.

## 8. 완료 기준

- `/terms`, `/privacy`, `/business` 세 URL이 열리고 위 콘텐츠를 보여준다.
- 랜딩 푸터에서 세 페이지로 이동할 수 있다.
- 사업자 값이 `COMPANY` 한 곳에서만 정의된다.
- `npm run test`·`npm run typecheck`·`npm run lint` 통과.
