# 랜딩 → 홈 흐름 설계 (2026-08-16)

피벗 이후의 첫 동선을 붙인 기록. 대상 이슈는 [B24 #51] 카드 컴포넌트 · [B26 #53] 랜딩 교체 ·
[B08b #33] 라이트 퍼널 · [B10 #35] 리빌 · [B25 #52] 홈 교체.

시안은 claude.ai/design 프로젝트 `42e876d6-1a2a-488e-93aa-825a838687ce` 의
`Character Card` · `Saju Pivot Flow` · `Saju Character Reveal` · `Saju Home`.
로컬에 없으면 DesignSync MCP 의 `get_file` 로 받는다 (`design/pivot/README.md` 참고).

## 흐름

```
/ (랜딩) → /start (생년월일 1스텝) → /reveal (리빌) → /home (탐색 허브)
                                                        ├ 리포트  → /report?profile=…  (없으면 /funnel)
                                                        ├ 관계 지도 → /map
                                                        └ 궁합    → 자리만
```

기존 다섯 스텝 퍼널(`/funnel`)은 그대로 남는다. 시각·출생지·성별이 필요한 유료 리포트용이다.

## 결정

### 1. 생년월일을 저장하지 않는다

라이트 퍼널은 계산이 끝나면 **60갑자 순번(0~59)과 (선택) 이름만** 쿠키에 담고 생년월일은 버린다.
화면이 "생일은 캐릭터 계산에만 사용" 이라고 말하는데 실제로는 Redis 에 원문이 남는 구조를 두지
않기 위해서다. 담는 것이 작아서 프로필 드래프트(`src/lib/drafts/`, Redis + 토큰 쿠키)를 쓸 이유도
없다 — `src/lib/characters/anon.ts` 의 쿠키 한 장이면 된다.

쿠키는 서명하지 않는다. 값을 조작해도 자기 카드만 바뀌므로 신뢰 경계가 아니다. 대신 읽을 때마다
zod 로 검증하고, 깨졌으면 없는 것으로 본다.

### 2. 홈은 로그인을 요구하지 않는다

기존 `/home` 은 세션이 없으면 `/login` 으로 보냈다. 무료 캐릭터로 사람을 모으는 흐름이 로그인
벽에서 끊기면 피벗이 성립하지 않으므로 이 가드를 걷었다.

- 로그인 + 프로필 있음 → 프로필들이 셀렉터에 선다
- 그 밖 + 쿠키 있음 → 익명 캐릭터 한 장
- 둘 다 없음 → 빈 상태(시안에 없는 화면) + `/start` CTA

로그인했는데 프로필이 있으면 익명 캐릭터는 덮어쓰지 않는다. 저장된 것과 저장되지 않은 것이
한 목록에 섞이면 무엇이 남는지 알 수 없다.

### 3. `buildPillars` 를 갈라낸다

`BirthInput.gender` 는 대운 방향에만 쓰이는데 타입상 필수라, 성별을 묻지 않는 입구는 가짜 값을
넣어야 했다(다른 브랜치의 `dayPillarOf` 가 `gender: "male"` 을 주석과 함께 넣고 있다).
간지는 성별과 무관하므로 `buildChart` 에서 성별 없는 `buildPillars` 를 떼어냈다.
`characterFromBirth(생년월일)` 가 그 위에 선다. 두 브랜치가 합쳐질 때 `dayPillarOf` 의
`gender: "male"` 은 지울 수 있다.

### 4. 서버 액션으로 제출한다

생년월일을 쿼리 파라미터로 넘기면 리퍼러·브라우저 기록·서버 로그에 남는다. `/start` 는 서버
액션(`app/start/actions.ts`)으로 POST 받아 계산·쿠키 설정까지 끝내고 `/reveal` 로 리다이렉트한다.
레포에서 서버 액션을 쓰는 첫 자리다 — 기존 퍼널은 클라이언트 fetch + `/api/profiles` 를 쓴다.

### 5. 리빌 → 홈 핸드오프는 sessionStorage

`/home?from=reveal` 로 두면 새로고침·링크 공유 때마다 연출이 다시 재생된다. 한 번 쓰고 지우는
값이어야 해서 `sessionStorage`(`saju:handoff`)로 나른다. 홈은 state 가 아니라 ref 로 클래스를
붙인다 — 서버에는 스토리지가 없어 첫 렌더에 알 수 없고, state 로 두면 그 사실 하나 때문에 전체가
한 번 더 그려진다.

## 카드 컴포넌트가 크기를 다루는 방식

시안 그대로 **1080px 캔버스에 그리고 `zoom: zoomW/1080` 으로 줄인다.** 폭마다 폰트를 다시 잡으면
장면명 한 줄·칩 줄바꿈·한자 위치가 따로 논다. `zoomW` 를 `w` 보다 작게 주면 글자 크기와 높이는
그대로 두고 가로만 늘어난다(홈 데스크톱이 `w=500 / zoomW=460`).

`zoom` 은 CSS 로 계산할 수 없어 폭을 숫자로 받아야 한다. 그래서 카드를 쓰는 화면은
`useViewportWidth()` 로 실제 폭을 재는 클라이언트 컴포넌트다. 서버 렌더는 모바일 폭(390)으로
시작한다 — 데스크톱에서 한 번 커지는 쪽이 모바일에서 잘려 보이는 쪽보다 낫다.

한자 워터마크 폰트(Nanum Myeongjo)는 Google Fonts 기본 URL 로 받는다. `&text=` 서브셋 경로
(`fonts.gstatic.com/l/font`)는 CORS 헤더를 주지 않아 `@font-face` 로드가 차단된다.

## 시안과 다르게 한 것

- **랜딩 푸터** — 시안에는 로고 한 줄뿐이지만 법률 링크·사업자정보를 남겼다. 통신판매업자 표시 의무다.
- **다크 섹션의 궁합 줄** — "지금" → "준비 중". 화면이 아직 없다.
- **홈 액션 그리드의 궁합** — 링크 대신 자리만. 링크로 두면 막다른 길이 된다.
- **모바일 경계** — 시안 760px, 구현 768px(Tailwind `md:`). 8px 어긋나면 그 구간에서만 카드 폭과
  단 수가 따로 논다.
- **생년월일 입력** — 시안은 네이티브 date picker 한 칸이지만 기존 퍼널의 년/월/일 세 칸을 썼다
  (B08a 의 "기존 퍼널 스텝2 컴포넌트 변형"). 윤달 체크는 그 달에 실제로 윤달이 있을 때만 묻는다.

## 하지 않은 것

- **공유** — B10 에서 폐기된 항목(공유 버튼·수신자 화면·미니 도감)은 만들지 않았다.
- **OG 이미지** (B11) — 별도 이슈.
- **`/map`** — `claude/wireframe-design-planning-d51640` 에 있다. 홈에서 링크만 걸어 두었고,
  그 브랜치가 합쳐지기 전에는 404 다.
- **60종 렌더 스냅샷 육안 검수** — 60종이 파라미터만으로 렌더되는 것은 테스트로 확인했지만
  대비·줄바꿈을 눈으로 본 것은 대표 몇 종뿐이다.
- **로그인 사용자의 홈** — 프로필 → 캐릭터 매핑은 단위 테스트로만 확인했다(브라우저 확인은 익명 경로).
