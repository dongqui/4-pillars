# 관계 지도 명칭 핸드오프

작성일: 2026-09-29
대상 커밋: `b5c98aa`
범위: `/map` 의 **사람-facing 이름** — 15개 별명, 5구역 이름, 六合/沖 표기.
지도의 배치(`_lib/radial.ts`)·색(`_data/role-colors.ts`)·궁합 카피의 오행 문장은 이름을 바꿔도 건드릴 필요가 없다(§6).

## 1. 이름이 사는 곳

전부 [`src/app/map/_data/roles.ts`](../../../src/app/map/_data/roles.ts) 한 파일이다. 컴포넌트는 문자열을 갖지 않는다.

| 상수 | 줄 | 칸 수 | 쓰이는 곳 |
| --- | --- | --- | --- |
| `DISPLAY_TITLES` | 41 | 15 (Role×Feature) | 지도 배지, 목록 행 태그, 노드 aria-label |
| `ROLE_REGION_NAME` | 57 | 5 | 목록의 구역 머리말 |
| `ROLE_LABELS` | 18 | 5 | **아무 데도 안 쓴다** (§7) |
| `FEATURE_LABELS` | 28 | 2 | **아무 데도 안 쓴다** (§7) |

### 현재 15칸

| Role (내부 키) | 기본 `none` | 六合 `yukhap` | 沖 `chung` |
| --- | --- | --- | --- |
| `fill` 나를 채워주는 사람 | 배터리 | 비타민 | 쓴약 |
| `beside` 나란히 서는 사람 | 동지 | 단짝 | 라이벌 |
| `express` 나를 표현하게 하는 사람 | 놀이터 | 뮤즈 | 버튼 |
| `move` 나를 움직이게 하는 사람 | 알람 | 찰떡 | 부싯돌 |
| `refine` 나를 다듬는 사람 | 울타리 | 신호등 | 회초리 |

`ROLE_REGION_NAME` 은 별도 표가 아니라 `DISPLAY_TITLES[role].none` 을 그대로 참조한다 — 지금은 기본 열(배터리·동지·놀이터·알람·울타리)이 곧 구역 이름이다. 구역 이름을 별명과 떼고 싶으면 이 참조를 끊고 다섯 문자열을 직접 적으면 된다. 원래 그러라고 따로 둔 상수다.

### 내부 키는 이름이 아니다

`fill/beside/express/move/refine` 과 `none/yukhap/chung` 은 명리 분류에서 기계적으로 나온다 — `_lib/to-map-people.ts:25`(생아=인성→`fill`, 비아=비겁→`beside`, 아생=식상→`express`, 아극=재성→`move`, 극아=관성→`refine`), 배지는 육합→`yukhap`, 충→`chung`. **표시명만 바꾼다면 이 키는 건드리지 않는다.** 키를 바꾸면 `radial.ts` 의 15슬롯, 색, 시드 스크립트, 테스트가 전부 따라온다.

## 3. 테스트가 잠근 제약

`_data/roles.test.ts` — 새 이름을 넣으면 여기부터 깨진다.

1. **15칸 전부 채움.** `Record<RelationRole, Record<Feature, string>>` 라 하나라도 빠지면 컴파일 단계에서 막힌다.
2. **15개가 서로 다름.** 겹치면 배지만 보고 어느 칸인지 알 수 없다.
3. **전부 3자 이내, 공백 없음.** 배지가 `w-[52px]` 고정이고, 15칸이 다 찬 지도에서 이웃 배지 중심 거리가 모바일에서 55.42px 뿐이다(`radial.ts:314` 주석). 4자를 넣으면 테스트는 이 규칙으로 막고, 억지로 통과시키면 화면에서 배지가 겹친다. **"보조배터리" 같은 옛 이름으로 되돌릴 수 없는 이유가 이것이다.**
   - 단서: 55.42px 는 지도 영역이 420px 였을 때의 측정값이고, `8ccd315`(목록이 지도를 덮는 시트가 됨) 이후 다시 재지 않았다. 배율이 폭(375px)에 묶여 있어 값은 그대로일 가능성이 높지만 — 그리는 세로폭이 332px 로 375 보다 작다 — **글자 수를 늘리려면 먼저 다시 재는 것이 맞다.**
4. **六合 계열과 沖 계열의 글자 수 총합 차이 ≤ 3.** 현재 六合 12자(비타민·단짝·뮤즈·찰떡·신호등) / 沖 13자(쓴약·라이벌·버튼·부싯돌·회초리), 차 1. 한쪽 계열만 길거나 짧아지면 그 순간 좋은 관계 / 나쁜 관계로 읽힌다는 원칙의 기계적 장치다.

원칙 자체(§ 스펙 §2): **판단하지 않는다. 六合 과 沖 은 같은 무게.** 沖 별명은 "나쁨"이 아니라 "쓸모 있는 마찰"로 쓴다.

## 4. 이름과 같이 움직여야 하는 것 — 궁합 단락 15칸

`_data/relation-notes.ts:86` 의 `NICKNAME_NOTE` 가 별명 열다섯과 1:1 짝이다. 목록 행을 펼치면 나오는 2~3문장이 그것이다.

별명 단어가 단락 안에 **글자 그대로 들어간 칸은 `express/chung` "버튼" 하나뿐**이고, 나머지 열넷은 심상으로만 받는다(배터리→"힘이 남아 있습니다", 회초리→다듬는 장면). 그래서 이름을 바꿔도 컴파일도 테스트도 안 깨지지만, **심상이 어긋난 채로 조용히 남는다.** 이름을 손대면 이 열다섯 칸을 눈으로 같이 읽어야 한다.

`relation-notes.test.ts` 가 거는 것: 15칸 채움 / 15개 서로 다름 / **구역마다 六合 단락과 沖 단락의 길이 비 ≥ 70%**.

## 5. 지금 다른 이름이 돌고 있는 곳 — `/match`

`src/lib/saju-core/relationship.ts:43,51` 에 **두 번째 이름 세트**가 있고, 궁합 페이지(`/match`)가 쓴다.

| | 이름 |
| --- | --- |
| `RELATION_LABELS` (5분류) | 귀인 · 단짝 · 내 사람 · 오른팔 · 스승 |
| `BADGE_LABELS` (배지) | 찰떡(육합) · 불꽃(충) · 쌍둥이(동일일주) |

주석에 "B01 확정 전 임시안"이라고 적혀 있다. 지도와 **같은 축을 다른 말로 부르고 있고, 단어가 두 개 겹친다**:

- **단짝** — 궁합에서는 `비아`(=지도의 `beside` 구역 전체), 지도에서는 `beside/yukhap` 한 칸.
- **찰떡** — 궁합에서는 육합 배지(=지도의 `yukhap` 열 전체), 지도에서는 `move/yukhap` 한 칸.

한 사람이 두 화면을 오가면 같은 단어가 다른 범위를 가리킨다. 이번에 지도 이름을 손본다면 **여기까지 한 번에 정리할지 먼저 정하는 편이 낫다.** 지도만 바꾸면 겹침이 남고, 둘 다 바꾸면 `/match` 의 `to-match-view.ts` 와 `relationship.test.ts:69`(`귀인` 리터럴), `synastry.test.ts:114` 가 따라온다.

## 6. 안 건드려도 되는 것

- **`ELEMENT_BRIDGE`** (`relation-notes.ts:41`, 25칸) — 내 일간 오행 × 구역의 오행 문장이다. 별명이 아니라 **구역의 뜻**에 달려 있어서, 이름만 바꾸면 그대로 맞는다. 구역의 의미 자체를 재정의할 때만 본다.
- **색** (`_data/role-colors.ts`) — Role 키에 붙어 있다.
- **배치** (`_lib/radial.ts`) — 15슬롯은 Role×Feature 키로 돈다. 다만 `BADGE_PX.width = 52` 는 §3-3 의 근거라 이름을 길게 하려면 여기부터 바꿔야 하고, 그러면 겹침 불변식(`radial.test.ts`)을 다시 재야 한다.
- **시드 스크립트** (`scripts/seed-map.mts`) — 별명을 하드코딩하지 않는다. 사람 이름만 `NAMES` 배열에서 꺼낸다.

## 7. 이미 어긋나 있는 것 (바꾸기 전에 알고 있어야 함)

1. **스펙 문서가 옛 이름이다.** `docs/superpowers/specs/2026-08-17-relationship-15-regions-design.md` §6 표는 **보조배터리 · 불쏘시개 · 가드레일** 로 되어 있다. `6518231 fix(map): 배지 폭을 줄여 화면 겹침을 없앤다` 에서 3자 제한이 생기며 배터리 · 부싯돌 · 울타리로 줄었는데 문서는 그대로다.
2. **원격 시안도 옛 이름이다.** Claude Design `사주` 프로젝트의 `Saju Relationship Map.dc.html` 의 `GROUPS` 가 `보조배터리 / 동지 / 놀이터 / 알람 / 가드레일` 이다. 시안을 근거로 이름을 정하면 3자 제한에 걸린다.
3. **죽은 상수 둘.** `ROLE_LABELS`("나를 채워주는 사람" 같은 문장 5개)와 `FEATURE_LABELS`(六合/沖)는 `roles.ts` 와 그 테스트 밖에서 아무도 안 쓴다. 이름을 새로 짤 때 **살릴지 지울지** 같이 정하면 좋다 — 별명만으로 뜻이 안 잡히면 `ROLE_LABELS` 가 툴팁이나 구역 머리말의 부제로 쓸 자리가 있다.

## 8. 바꿀 때 순서

1. `roles.ts` 의 `DISPLAY_TITLES` 를 고친다. 구역 이름을 별명과 떼려면 `ROLE_REGION_NAME` 의 참조를 끊는다.
2. `relation-notes.ts` 의 `NICKNAME_NOTE` 15칸을 새 심상에 맞춰 읽고 고친다(§4).
3. `/match` 와의 겹침을 정리할지 정한다(§5).
4. 스펙 문서 §6 표와 원격 시안을 새 이름으로 맞춘다(§7).
5. 검증:

```bash
npx vitest run src/app/map src/lib/saju-core && npx tsc --noEmit && npx eslint src/app/map
```

배지 겹침은 테스트가 잡아 주지만(3자 제한), 눈으로 볼 때는 인원 50명 시드가 제일 빡빡하다:

```bash
npm run map:seed -- --count 50 --reset
```
