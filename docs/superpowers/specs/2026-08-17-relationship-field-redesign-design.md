# 관계 Field 재설계 설계 문서

**날짜:** 2026-08-17
**선행 문서:** `2026-08-16-relationship-world-spike-design.md` (1차 스파이크)
**대상 라우트:** `/lab/relationship-world`

## 1. 왜 다시 만드는가

1차 스파이크는 5개 관계 공간을 성운으로 표현했다. 실제로 띄워보니 **다섯 개가 전부 비슷한 흰 파티클 덩어리**라 서로 다른 공간으로 느껴지지 않았다. 화면은 관계 세계가 아니라 은하 클러스터로 읽혔다.

원인은 구조에 있다. `Nebula.tsx` 하나에 `count`/`size`/`opacity`/`tint`만 바꿔 다섯 번 렌더한다. 같은 알고리즘에 숫자만 다르니 다섯 개가 같은 것으로 보이는 게 당연하다.

우주 컨셉은 유지한다. 섬·지형으로 바꾸면 바닥 평면에 얹혀 2.5D 느낌이 강해지고, 3D 공간처럼 보이게 하려는 방향 자체는 옳았다.

바뀌는 것은 한 줄로 정리된다.

> **"우주에 5개의 섬을 놓는 것"이 아니라
> "우주 안에 성질이 다른 5개의 관계 Field가 존재하는 것"**

## 2. 범위 결정 (확정됨)

| 항목 | 결정 |
| --- | --- |
| 우주 컨셉 | **유지.** 섬/지형으로 바꾸지 않는다. |
| Field 구분 | **형태와 공간의 성질로 구분.** 색은 보조. |
| 셰이더 | **커스텀 GLSL 허용.** 단 픽셀당 연산이 가벼운 수준으로 제한 (§7). |
| 색 | **미묘한 색온 차이만.** 재질에서 자연스럽게 나오는 정도이며 오행 라벨이 아니다. |
| 파티클 | **강등.** 경계·분위기 암시용 보조 요소로만. |
| 진입 프레이밍 | **5개를 다 담지 않는다.** 나 + 인접 2~3개 Field가 크게. (§6) |
| Role / Feature | **원칙 유지.** Role = 공간, Feature = 현상. |

### 비범위 (YAGNI)

1차 스파이크의 비범위를 그대로 승계한다 — 실제 Relationship DB, 프로필 저장/전환, 십성 계산 연결, 15개 Archetype, 형/파/해/삼합, 궁합 점수, 60종 일러스트, physics, WebGPU, 결제.

이번에 추가로 하지 않는 것:

- **레이마칭 볼륨.** 폰 GPU에서 프레임이 무너진다 (§7).
- **포스트프로세싱 파이프라인** (bloom, DOF 등). 효과당 풀스크린 패스가 추가되고, 예뻐 보이는 대신 무엇이 느린지 판단이 흐려진다.
- **Field 간 상호작용.** 겹치는 두 Field가 서로 반응하는 표현은 만들지 않는다.
- **접근성 전면 대응.** 1차와 같은 이유로 미룬다.

## 3. 5개 Field

각 Field는 **자기 컴포넌트와 자기 기하 전략**을 갖는다. 공통 파라미터로 흉내 내지 않는다.

| Role | 성질 | 기하 전략 |
| --- | --- | --- |
| `fill` 나를 채워주는 사람 | 감싸는 volume / mist | 동심 셸 3~4겹. fresnel + 노이즈로 가장자리만 밝고 안쪽은 비는 안개. 아주 낮은 알파, 느린 호흡. |
| `beside` 나란히 서는 사람 | 넓게 펼쳐진 layer / parallel flow | 얇고 넓은 평행 판 여러 장. 판 위를 한 방향으로 흐르는 streak. |
| `express` 나를 표현하게 하는 사람 | 바깥으로 퍼지는 light / rays | 코어에서 방사되는 광선 스트립. additive, 거리에 따라 감쇠. |
| `move` 나를 움직이게 하는 사람 | 흐르는 ribbon / stream | 곡선 경로 위 튜브 리본 몇 가닥. UV 흐름 애니메이션. |
| `refine` 나를 다듬는 사람 | crystal / shard / structured field | 각진 파편들을 **격자로 정돈** 배치. 굴절감 있는 재질, 느린 회전. |

### `refine`이 격자인 이유

나머지 넷이 전부 유기적이라, 하나만 규칙적으로 놓이면 "정돈됨"이 색이나 라벨 없이 형태만으로 읽힌다. 랜덤 배치로는 이 대비가 생기지 않는다.

### 색

다섯 개는 좁은 한색 계열 안에 머문다. 차이는 재질에서 자연스럽게 나오는 색온 정도다 — 결정은 차갑게, 안개는 따뜻하게. **어떤 Field도 오행을 지시하지 않는다.** 구분의 부담은 전부 형태가 진다. 색만 빼고 봐도 다섯이 구분되어야 한다.

## 4. 파티클 강등

지금 5개 성운이 파티클 4,620개로 화면을 채운다. 이게 "은하 클러스터처럼 보인다"의 직접적 원인이다.

- Field당 파티클 **100~200개**로 줄인다. 부피를 채우지 않고 **경계와 분위기만 암시**한다.
- 본체는 볼륨·판·광선·리본·결정이 맡는다.
- 배경 별먼지는 유지하되 밀도를 낮춘다. 별은 배경이지 내용이 아니다.

## 5. 사람을 명확하게

### 3D 앵커를 준다

지금 사람은 DOM 명패뿐이라 **3D 상의 실체가 없다.** 그래서 카메라를 돌려도 앞뒤가 느껴지지 않는다.

각 사람에게 작은 발광 노드를 3D로 두고, 이름표를 그 위에 붙인다.

- 노드는 Field 지오메트리에 **가려지고** 원근으로 크기가 변한다 → 깊이가 실제로 읽힌다
- 이름은 DOM이라 **계속 선명하다** → 가독성은 유지된다

이 둘을 분리하는 것이 핵심이다. 깊이는 3D가, 가독성은 DOM이 맡는다.

### 깊이 방향으로 벌린다

지금은 구면 분포라 같은 Field 안에서 깊이 차이가 약하다. **Field의 성질에 맞는 축으로** 사람을 배치한다 — 층이면 층 사이에, 리본이면 흐름을 따라, 결정이면 격자 위에. 배치가 Field 형태와 따로 놀면 사람이 공간에 속해 보이지 않는다.

### 이름 가독성

1차의 3단계 LOD(full/compact/dot)는 유지하되, 진입 프레이밍이 바뀌어 **한 화면에 들어오는 사람 수가 줄어들므로** 경계값을 다시 잡는다. `dot`(이름 없음)으로 떨어지는 빈도를 낮추는 방향이다.

## 6. 진입 프레이밍 — 1차의 테스트를 뒤집는다

1차 최종 수정에서 넣은 `layout.test.ts`의 두 테스트가 이번 방향과 정면으로 충돌한다.

- "사람 20명 중 18명 이상이 화면 안에 들어온다"
- "성운 중심 5개가 전부 화면 안에 들어온다"

**둘 다 삭제한다.** 그리고 목적이 다른 세 가지로 교체한다.

| 새 불변식 | 지키는 것 |
| --- | --- |
| 나(원점)는 항상 화면 안 | 기준점을 잃지 않는다 |
| 진입 시 Field 중심 **2~4개**가 화면 안 | 빈 화면도 아니고 전부 보이지도 않는다 — 둘러볼 여지가 남는다 |
| **모든 Field가 카메라 제한 안에서 도달 가능** | 못 가는 곳은 없다 |

세 번째가 "길을 잃지 않는다"를 실제로 지키는 장치다. 다 보이지 않아도 되지만, 카메라 제한 때문에 영영 못 가는 Field가 있으면 안 된다.

"도달 가능"의 정의를 못 박아 둔다 — **각 Field의 중심이 화면 안에 들어오는 카메라 자세가 세 모드 각각의 제한 범위 안에 하나 이상 존재한다.** Field 전체가 프레임에 들어올 필요는 없다. 검증은 제한 범위(polar·azimuth·distance)를 격자로 훑어 그런 자세가 있는지 찾는 방식으로 한다.

카메라 기본 거리는 1차에서 ×3.077로 밀어냈던 것을 되돌린다. 전부 담을 필요가 없어졌기 때문이다. `NEAR`/`FAR`, `FOCUS_DISTANCE`, fog도 함께 다시 잡는다.

## 7. 성능 — 예쁘게 만들려다 판단을 망치지 않기

커스텀 셰이더 5종과 마커 20개가 **폰 GPU에서** 동시에 돈다. 이건 실제 위험이다.

| 제약 | 이유 |
| --- | --- |
| **레이마칭 금지** | 볼륨은 겹친 셸 + 노이즈로 흉내 낸다. 픽셀당 루프는 폰에서 무너진다. |
| 셰이더는 픽셀당 연산 최소 | 노이즈는 저주파 몇 옥타브까지. 프랙탈 노이즈 다층은 쓰지 않는다. |
| 큰 반투명 면 겹침 최소화 | 오버드로가 폰에서 가장 비싸다. `beside`의 평행 판 장수를 제한한다. |
| 포스트프로세싱 없음 | §2 비범위 |

예쁘게 만들려다 폰에서 버벅이면 **"3D가 별로다"라는 잘못된 결론**이 나온다. 1차에서 카메라 산술 하나 때문에 스파이크 전체가 판단 불가였던 것과 같은 실패 모드다.

## 8. 유지되는 원칙

1차에서 확립한 것들을 그대로 승계한다.

- **Role = 공간 / Feature = 현상.** 六合·沖은 Field를 만드는 데 일절 쓰지 않는다. 사람을 선택했을 때 나 ↔ 상대 사이의 빛·흐름·진동으로만 나타난다.
- **거리는 궁합이 아니다.** `positionFor(role, indexInRole)`는 `feature`를 받지 않고, `placePeople`이 받는 `Placeable`에는 `feature` 필드가 없다. 타입이 막는다. 이 테스트는 그대로 둔다.
- **六合과 沖은 같은 색, 같은 렌더 불투명도.** 움직임의 질로만 다르다.
- **`feature: "none"`은 완전히 침묵한다.** 배지도 라벨도 "중립"이라는 개념도 없다.
- **한글은 WebGL 안에 넣지 않는다.**
- **`src/app/globals.css`를 수정하지 않는다.**
- **`Math.random()`을 쓰지 않는다.** 시드 해시만.
- **전역 상태 라이브러리를 추가하지 않는다.**
- 라우트는 색인되지 않고 어디서도 링크되지 않는다.

## 9. 파일 구조

```
_components/
  fields/
    FillVolume.tsx        감싸는 안개
    BesideLayers.tsx      평행 층
    ExpressRays.tsx       방사 광선
    MoveRibbons.tsx       흐르는 리본
    RefineShards.tsx      정돈된 결정
    FieldRegistry.tsx     role -> 컴포넌트 매핑 + 공통 dim 처리
    shaders/              GLSL 문자열
  PersonNode.tsx          3D 발광 노드 (신규)
  PersonMarker.tsx        DOM 이름표 (노드에 붙도록 수정)
```

`Nebula.tsx`는 삭제한다. 다섯 Field가 각자 컴포넌트를 가지면 이 파일이 할 일이 남지 않는다.

`_lib/layout.ts`의 `NEBULA_CENTERS`/`NEBULA_SPREAD`는 `FIELD_CENTERS`/`FIELD_EXTENT`로 이름을 바꾼다 — 더 이상 성운이 아니다.

## 10. 판단 기준

375px 실기기에서 확인한다.

- **5개 Field가 서로 다른 공간으로 느껴지는가** — 이번 재설계의 존재 이유
- 색을 빼고 봐도 구분되는가
- 카메라를 돌렸을 때 각 영역의 깊이와 구조가 다르게 느껴지는가
- 사람 이름과 노드가 명확한가 / 앞뒤 관계가 느껴지는가
- 드래그해서 작은 우주를 둘러보는 재미가 있는가
- **폰에서 부드럽게 도는가** (§7)
- 여전히 차트로 보이지 않는가

그리고 1차와 같은 질문이 남는다.

> **"이 화면을 처음 봤을 때 2D 관계 차트보다 확실히 더 매력적이고 기억에 남는가?"**

## 11. 알려진 리스크

| 리스크 | 대응 |
| --- | --- |
| 셰이더 5종이 폰에서 느림 | §7의 제약. 레이마칭 금지, 오버드로 제한 |
| 형태를 다르게 했는데도 여전히 비슷해 보임 | 색을 끄고 실루엣만으로 구분되는지 먼저 확인. 안 되면 형태 대비를 더 벌린다 |
| 반투명 Field가 사람 노드를 가림 | 노드는 Field보다 뒤에 그리지 않는다. 가림은 깊이 신호로만 쓰고 완전히 묻히지 않게 한다 |
| 진입에 Field가 2개도 안 보임 | §6 불변식이 테스트로 막는다 |
| 우주가 다시 "노드 그래프"로 보임 | Field는 부피를 가진 영역이고 사람은 그 안에 속한다. 1차와 같은 방어 |
